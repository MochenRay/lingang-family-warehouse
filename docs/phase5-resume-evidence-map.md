# 临港家庭数仓 Phase 5 简历证据映射

> 日期：2026-04-18
> 对应任务：`T53`
> 用途：把简历表述、页面证据和验证文档对齐，避免面试时“简历能写、Demo 里找不到”

## 1. 使用原则

- 简历里的每一条能力描述，都必须能在当前系统页面或验证文档里找到证据
- 如果某项能力当前只是“样例能力”，简历里必须带限定词
- 优先写“你做了什么”和“系统最终呈现了什么”，不要写空泛大词

## 2. 推荐简历 Bullet（可直接改写）

### Bullet 1：产品主导

> 主导社区治理智能中台 Demo 的产品结构设计，围绕“驾驶舱研判 -> 对象画像 -> 处置闭环 -> 移动端执行”搭建 Web 管理端与移动端工作台双端联动主链。

### Bullet 2：AI 能力设计

> 将 AI 能力拆分为数据画像、研判调度、社工助手三类业务内嵌能力，避免停留在孤立聊天页，落到画像摘要、风险提示、待办建议、走访记录与处置建议等具体动作。

### Bullet 3：业务建模

> 抽象人口、房屋、人房关系、走访、矛盾、待办、标签、公告、知识等核心对象模型，形成统一数据骨架，支撑桌面端和移动端围绕同一套对象链协同演示。

### Bullet 4：Demo 交付

> 将高保真前端原型继续重构为可在线演示、可自由浏览、可重复部署的作品集级系统，补齐后端、演示数据、正式验证文档和部署 runbook。

## 4. 页面到能力的最短映射

### 如果面试官问“你最拿得出手的页面是哪几个”

建议回答：

- `综合统计驾驶舱`
- `人口管理`
- `矛盾调解`
- `移动端待办`
- `移动端人员详情 / 走访记录`

### 如果面试官问“AI 体现在哪”

建议回答：

- 管理端：画像、风险、调度建议
- 处置端：矛盾上下文和动作建议
- 一线端：走访前准备、走访记录整理、待办生成

### 如果面试官问“你做的不是纯原型吗”

建议回答：

> 原型是起点，但我后来继续把它重构成了一个可验证的作品：补了后端、演示数据、统一对象模型、验证文档和可重复部署方式，所以它现在不只是静态原型展示。

## 5. 不建议写进简历的表述

- “已上线服务数万用户”
- “完整大模型智能体平台”
- “完整 RAG 知识库系统”
- “企业级权限与审计体系”
- “生产级规则引擎”

这些要么当前没做，要么不是这个项目该承担的卖点。

## 6. 最适合简历里的能力标签

可以考虑：

- 智能中台产品设计
- 社区治理/网格治理数字化
- AI 产品能力设计
- 双端业务流程设计
- 复杂业务建模
- Demo 级产品交付与作品集包装

## 7. 面试时的推荐补充材料顺序

1. 简历 bullet
2. 在线链接
3. `phase5-demo-script.md`
4. `phase1-4 verification` 文档

逻辑是：

- 先让对方知道你做了什么
- 再让对方知道能不能点开验证
- 最后给出严谨证据，而不是一开始就甩长文档
