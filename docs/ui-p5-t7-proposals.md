## 方案一：WarningMap 整页重做

### 问题陈述

现页（`WarningMap.tsx`，309 行）结构为 KPI 行 + 8 块网格热区板 + 预警清单 + 详情 Dialog，与「地图」名实不符——页面自述「用网格热区板替代空地图视图」（`:192`）。经核实，**全系统无任何地理坐标数据**：Grid/House/Person/ConflictRecord 模型与 seed 零坐标字段（grep `lat|lng|lon|coord|经纬` 于 backend 零命中），前端无地图库（`package.json` 仅 recharts 2.15.2），唯一空间锚点是「区→街道→社区→网格」文本层级（`regions.ts` + Grid 树）。按冻结裁决：**无坐标不做真地图**。

附加问题：
- **命名分裂**：同一页在四处称谓不一——路由 id `heatmap`、页面标题「预警地图」（`WarningMap.tsx:135`）、角色权限「热力图分析」（`RoleManagement.tsx:113`）、权限管理「全域人口热力图」（`PermissionManagement.tsx:49`）。
- **导航隐藏**：该页不在 Sidebar 任何分组（`Sidebar.tsx:46-122` 无条目），只能直接输 URL 到达。
- 信息层级平铺：热区板（`grids.slice(0, 8)`）与预警清单（≤12 条）并列堆砌，层级（区/街道/社区）与优先级（heatScore）没有被视觉结构化。

### 结论：结构重做（非视觉再设计）

视觉再设计解决不了「名实不符 + 层级缺失 + 命名分裂」；真地图无数据支撑。方案为「热区矩阵化」的结构重做。

### 目标用户与阅读效率目标

- 一线网格员/网格长：10 秒内回答「我辖区哪个社区最烫、烫在哪类信号」。
- 管理者：30 秒内完成「等级分布 → 热区 Top → 具体预警 → 详情」的下钻路径。

### 结构草图

```
┌ PageHeader：预警热区（改名，见决策点①）────────────────┐
│ 筛选：类型 Select / 等级 Select / 导出 JSON（保持现状）      │
├ KPI 行（6 卡，保持现状口径）─────────────────────────────┤
├ 热区矩阵（新）─────────────────────────────────────────┤
│ 按 区→街道 分组（regions.ts 层级），每组内社区热区板          │
│ 按 heatScore 降序排列；板面元素=现状（名称/信号数/等级        │
│ Badge/热度分/待处理/已闭环/主信号），点击选中行为保持          │
├ 预警清单（保持，按网格分组显示）──────────────────────────┤
├ 详情 Dialog（保持现状）──────────────────────────────────┤
```

### 决策点（评审拍板）

1. **定名**：推荐「预警热区」（名实相符；eyebrow 同步 `WARNING HEATMAP`→`WARNING ZONES`）。备选保留「预警地图」。定名后页面标题、角色/权限演示配置（RoleManagement/PermissionManagement 两处）一并统一。
2. **是否补导航入口**：推荐补，落入「统计分析」组（path `/analysis/warning-map` 同域）——与方案二联动，若方案二通过则随其对照表落地。
3. **热区矩阵分组维度**：推荐按区/街道层级分组（regions.ts 已有层级数据），组内 heatScore 降序；不做加权尺寸（避免低保真「伪地图」感）。

### 验收标准（实施 PR）

- 全站称谓统一：页面标题/eyebrow、RoleManagement、PermissionManagement 演示配置同一名称；a11y 扫描该路由 readyText 同步更新且「阻断为零」硬断言通过
- 热区矩阵按层级分组渲染，筛选/点击/Dialog 行为与现状一致（e2e 覆盖）
- 1024×768 与 1440×900 截图无溢出；golden 机制不在试点页，无需基线

### 工作量估计

中（2–3 天）：页面结构重构 1 天、命名统一 + 权限配置同步 0.5 天、e2e + 截图 + a11y 复扫 0.5–1 天。

## 方案二：导航重组

### 问题陈述

桌面 Sidebar 为 7 组 29 项（`Sidebar.tsx:46-122`），隐藏第 30 项 `heatmap`（见方案一）。三处语义问题（冻结稿点名，代码证据已核）：

1. **「归因分析（示例）」名不副实**（`Sidebar.tsx:102`）：组内 4 页自身均为正式命名（异常结果分析/时序分析/影响因子识别/贡献程度排名），「示例」只存在于组名一层，与页面实际形态不一致。
2. **「标签管理」孤立项**（`Sidebar.tsx:72-76`）：7 组中唯一无 children 的顶层项；同族页「标签分析画像」却在「统计分析」组（`:56`），标签域 2 页被拆在 2 处。
3. **智能体/网格事务边界**：「待办规则」（rule-config，`:97`）语义偏配置却在事务组；`Routes.tsx` 分区注释（行为督导/规则引擎被视为独立域）与 Sidebar 分组不同步。

边界（冻结）：**不增删页面、不改路由 path**；移动端导航完全独立（`MobileLayout.tsx:14-19` 硬编码 4 tab），不在本方案范围。

### 目标用户与阅读效率目标

- 新用户：凭组名直觉猜中目标页所在组，一次展开命中。
- 高频用户：常用域（数据管理/网格事务）路径不变、肌肉记忆不受影响。

### 改动前后对照表（推荐方案）

| 分组 | 改动前 | 改动后 | 理由 |
|---|---|---|---|
| 统计分析 | 7 项（含标签分析画像） | 7 项：−标签分析画像，+预警热区（决策点：方案一定名后补入） | 标签域归并；隐藏页补入口 |
| 数据管理 | 4 项 | 不变 | 高频域不动 |
| 标签管理（孤立） | 1 项（自身即叶子） | **标签**（组改名）2 项：标签管理、标签分析画像（自统计分析移入） | 消除唯一单层组，标签域聚合 |
| 数仓智能体 | 4 项 | 不变 | 边界干净 |
| 网格事务 | 5 项（含待办规则） | 4 项：−待办规则 | 事务组保留执行类 |
| 归因分析（示例） | 4 项 | **归因分析**（组改名），4 项不变 | 去除与实态不符的「示例」 |
| 系统配置 | 4 项 | 5 项：+待办规则（自网格事务移入） | 规则配置归配置域 |

默认展开组保持 `statistics` + `data-management` 不变；「体验移动端工作台」底部入口不变。

### 决策点（评审拍板）

1. 待办规则是否移系统配置（推荐移；备选留网格事务——它是网格业务规则，两种语义都成立）。
2. 预警热区是否补入统计分析组（与方案一决策点②同一决策）。
3. 「标签」组名（推荐）vs 保留「标签管理」组名收编画像页。

### 验收标准（实施 PR）

- 对照表逐组落地；路由 path 零改动（grep 证明）；移动端零改动
- 菜单 label 程序化测量零溢出零换行（复用 T6 测量方法）；1024×768/1440×900/折叠态截图
- e2e：每组首项点击可达；a11y 扫描「阻断为零」

### 工作量估计

小（0.5–1 天）：Sidebar menuItems 重排 + 截图 + 冒烟。

## 方案三：人口金字塔 div → Recharts

### 问题陈述

现金字塔（`DemographicsAnalysis.tsx:90-154` 内部组件 `PopulationPyramid`）为 div 实现，存在四类不一致与一个数据失真：

- **数据失真（最重）**：数据源 `personRepository.getPeople({ limit: 500 })`（`:172`）——全库 1917 人，金字塔只统计前 500 条，比例结构失真。
- **主题不一致**：男用 `brand-primary-hover`、女用 `status-warning`（语义为「警告橙」），未用 chartConfig 的性别专用色 `CHART_GENDER_COLORS`（`chartConfig.ts:91-94`）。
- **交互不一致**：hover 仅原生 `title` 属性，无 `DarkChartTooltip`/cursor；无空数据态（空数据渲染全 0 条而非 EmptyState）。
- **口径分裂**：前端桶边界 60岁以上 min=60（`:27-28`），后端 `_build_age_data` 为 61（`stats.py:48-53`），60 岁者前后端归不同桶。
- 技术缺口：双向/负值条形全站无 Recharts 先例（grep `stackId` 零命中），本项为首例。

### 目标用户与阅读效率目标

- 分析用户：hover 任一性别段即见精确人数（与全站图表 tooltip 体验一致）；空数据时有明确空态而非「全 0 假象」。
- 数据可信：金字塔覆盖全量 1917 人而非前 500。

### 结构草图

```
┌ Card：年龄性别人口金字塔 ─────────────────────────────┐
│ Recharts BarChart layout="vertical"                     │
│  XAxis：镜像刻度（tickFormatter 取绝对值）                 │
│  YAxis：4 年龄段（对齐后端桶边界，见决策点②）               │
│  Bar male（负值法）← 中线 → Bar female                  │
│  Tooltip：DarkChartTooltip + DARK_TOOLTIP_CURSOR        │
│  配色：CHART_GENDER_COLORS（male #2761CB / female #E845B1）│
│  空数据：页面级 EmptyState（patterns/states）              │
│  加载：LoadingState（保持现状）                            │
```

### 数据层方案

- 修复 500 截断：改用 repository 全量读取（P3 阶段 repository 层已统一跨页读取并修复同类 500 截断；实施时优先复用既有全量方法，无则分页拉全量——**不改后端、不加聚合接口**）。
- 桶边界：对齐后端（60岁以上 = 61 起，见决策点②）。

### 决策点（评审拍板）

1. 双向实现方式：推荐负值法（male 取负、XAxis 镜像绝对值刻度），双 Bar 不 stack；备选双 Bar `stackId` 堆叠（首例引入）。以 Recharts 2.15.2 实测为准。
2. 桶边界对齐后端 61（推荐，消除前后端分裂；60 岁共 N 人归桶将变化，实施 PR 附前后对照）。备选保持前端 60 并改后端——涉及后端，不推荐。
3. 是否顺手统一 `dashboard.ageData` 顶部 StatCard 口径——推荐不做（控制范围，仅金字塔）。

### 验收标准（实施 PR）

- 交互一致性：DarkChartTooltip + cursor hover 生效；空数据 EmptyState；加载 LoadingState
- 数据正确：金字塔 = 全量人口逐桶计数（e2e 断言各桶男女数与 API 全量数据推算一致）
- 1024×768 不溢出截图 + 1440×900 截图；a11y 扫描「阻断为零」
- recharts JS 动画与 reduced-motion 的关系记录为已知项（全站一致，不单独立项）

### 工作量估计

小-中（1 天）：组件重写 0.5 天、e2e + 截图 0.5 天。
