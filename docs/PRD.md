## 第1章 文档概述

### 1.1 文档目的

本文档是威海市临港新片区"家庭数仓"系统的产品需求基准，面向开发团队、测试团队及客户方（临港新片区管理方），作为系统开发、测试与验收的唯一功能参照。

### 1.2 适用范围

- **Web 管理端**：面向社区管理人员、乡镇管理者、系统管理员
- **移动端**：山东通 H5 接入，面向基层网格员和社区工作者

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 家庭数仓 | 以家庭为单元，整合人、房、户全要素数据的社区治理数据底座 |
| 网格 | 社区治理最小管理单元，隶属于社区→乡镇→区县的层级体系 |
| 规则标签 | 基于预设条件（如年龄≥60岁）由系统自动计算生成的标签 |
| 智能标签 | 通过 AI 大模型分析非结构化文本后给出的建议标签，需人工确认生效 |
| 人房关系 | 人员与房屋的绑定关系，分为"现居"（当前居住）和"历史"（曾居住）两类 |
| 辖区层级 | 区县 → 乡镇/街道 → 社区 → 网格，四级行政管理体系 |
| 城市大脑 | 威海市统一数据平台，提供基础人口、房屋等数据接口 |
| 山东通 | 山东省统一政务移动办公平台，本系统通过其接入移动端 |
| 三色分级 | 基于风险标签的人员分级机制：红=高危、黄=关注、绿=正常 |

## 第2章 产品定位与目标

### 2.1 项目背景

威海市临港新片区在社区治理中面临三大痛点：

1. **数据碎片化**：人口、房屋、事件等数据分散在不同系统，口径不一、更新滞后
2. **服务被动化**：社区工作依赖居民主动反馈，缺少主动发现和精准推送能力
3. **工作模式传统化**：纸质台账、手工统计、经验决策，基层工作者负担重

### 2.2 产品定位

**家庭数仓** = 以家庭为单元的社区治理数据中台 + AI 赋能平台

核心理念：从"专项数据"向"家庭融合感知集合"转换，构建"房—户—人"三位一体的动态数据库。

### 2.3 核心价值

```
四维数据采集 → 家庭数仓数据底座 → 三大智能体 → 九大应用场景
```

- **数据底座**：全量覆盖、实时鲜活的居民/家庭/社区数据集
- **三大智能体**：
  - **数据管理智能体**：数据自动归集、关联、标签画像，确保"全、准、活"
  - **研判调度智能体**：任务自主推送、风险自主排查、服务对象自主筛选
  - **AI 社工助手**：辅助走访记录、方案制定、材料撰写、政策解读
- **九大场景**：信息管理、日常走访、活动组织、政策应用、问题处置、决策辅助、关心关爱、文书助手、督导考核

### 2.4 建设目标

| 目标维度 | 量化指标 |
|----------|----------|
| 数据覆盖 | 辖区人口、房屋数据覆盖率 ≥ 95% |
| 基层减负 | 网格员日常事务耗时降低 ≥ 30% |
| 走访效率 | 单次走访信息采集效率提升 ≥ 50% |
| 政策落地 | 政策匹配到目标人群周期缩短 ≥ 60% |
| 风险预警 | 重点人群动态感知覆盖率 ≥ 90% |

### 2.5 项目约束

- 安全等保：至少等保二级（建议三级）
- 认证对接：山东通统一认证
- 数据对接：城市大脑数据接口
- 网络环境：政务外网
- 合规要求：《个人信息保护法》《数据安全法》

## 第3章 用户角色与使用场景

### 3.1 角色定义

| 角色 | 使用端 | 核心职责 |
|------|--------|----------|
| 网格员 | 移动端为主 | 日常走访、信息采集、档案核验、待办处理 |
| 社区工作者 | 双端 | 活动组织、政策应用、问题处置、文书撰写 |
| 社区管理员 | Web 端 | 数据管理、标签管理、督导考核、决策辅助 |
| 乡镇/街道管理者 | Web 端 | 辖区总览、跨社区对比、研判简报审阅 |
| 系统管理员 | Web 端 | 用户/角色/权限/日志管理、系统配置 |
| 区级领导 | Web 端（大屏） | 全域态势感知、预警地图、宏观决策 |

### 3.2 典型用户故事

**网格员**
- 作为网格员，我需要在入户走访时快速调取居民画像和历史走访记录，以便有针对性地开展沟通
- 作为网格员，我需要用语音记录走访内容并自动转文字，以便减少手工填写负担
- 作为网格员，我需要收到系统自动推送的待办任务（如定期探访独居老人），以便不遗漏重点工作

**社区管理员**
- 作为社区管理员，我需要一键查看辖区人口结构变化趋势，以便及时发现异常波动
- 作为社区管理员，我需要配置标签规则（如"独居老人"）自动识别目标人群，以便精准开展关爱服务
- 作为社区管理员，我需要查看网格员的走访频次和质量评分，以便进行绩效考核

**乡镇管理者**
- 作为乡镇管理者，我需要查看多社区的横向对比数据和研判简报，以便制定资源调配方案

## 第4章 系统架构

### 4.1 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    展示层                             │
│   Web 管理端  │  移动端（山东通）  │  可视化大屏        │
├─────────────────────────────────────────────────────┤
│                    应用层                             │
│   九大应用场景（信息管理/走访/活动/政策/处置/          │
│               决策/关爱/文书/督导）                    │
├─────────────────────────────────────────────────────┤
│                    能力层                             │
│   数据管理智能体  │  研判调度智能体  │  AI社工助手      │
├─────────────────────────────────────────────────────┤
│                    数据层                             │
│   家庭数仓（人口库/房屋库/标签库/事件库/知识库）       │
├─────────────────────────────────────────────────────┤
│                  基础设施层                           │
│   政务云  │  GIS地图  │  城市大脑  │  山东通认证       │
└─────────────────────────────────────────────────────┘
```

### 4.2 双端架构

| 端 | 技术方案 | 说明 |
|----|----------|------|
| Web 管理端 | React 18 + TypeScript + Vite + Tailwind CSS 4 | 完整管理功能 |
| 移动端 | H5 页面，山东通内嵌 | 现场采集、快速查询、走访管理 |
| 后端 | **待定** | 需确定技术选型（候选：Java Spring Boot / Node.js + PostgreSQL） |

### 4.3 三大智能体

| 智能体 | 输入 | 输出 | 触发方式 |
|--------|------|------|----------|
| 数据管理智能体 | 多源原始数据、非结构化文本 | 结构化档案、自动标签、画像 | 数据入库时自动触发 |
| 研判调度智能体 | 数据底座 + 事件流 | 任务推送、风险排查、服务名单、研判简报 | 定时任务 + 事件驱动 |
| AI 社工助手 | 用户指令 + 上下文数据 | 走访提纲、文书、政策解读、处置建议 | 用户主动调用 |

### 4.4 数据流转（四维入库模式）

1. **批量导入**：Excel 模板 → 预校验 → 入库（存量数据初始化）
2. **动态更新**：走访采集、移动端录入 → 实时写入
3. **智能感知**：AI 标签引擎 → 非结构化文本分析 → 建议标签
4. **部门联动**：城市大脑接口 → 自动拉取 → 增量更新

### 4.5 外部集成

| 外部系统 | 集成方式 | 用途 |
|----------|----------|------|
| 山东通 | 统一认证票据 | 移动端登录、身份识别、组织权限同步 |
| 城市大脑 | API 接口 | 基础人口/房屋数据拉取 |
| 12345 热线 | 数据推送 | 问题处置场景的工单来源 |
| GIS 地图服务 | 地图 API | 热力图、预警地图、空间分析 |

## 第5章 数据模型设计

### 5.1 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|----------|
| **Person** | 人员档案 | 姓名、身份证、性别、年龄、电话、地址、人员类型（户籍/流动/留守/境外）、风险等级、标签集合 |
| **House** | 房屋档案 | 小区、楼栋、单元、房号、业主、面积、房屋类型、居住状态（自住/出租/空置） |
| **Grid** | 网格 | 名称、父级ID（支持层级）、网格长姓名 |
| **Tag** | 标签 | 名称、类别（identity/risk/health/other）、颜色 |
| **FamilyRelation** | 家庭关系 | 关联人员ID、关系类型（父母/配偶/子女/兄弟姐妹等） |

### 5.2 扩展信息（Person）

| 分组 | 字段 |
|------|------|
| 户主详细信息 | 出生日期、籍贯、婚姻状况、宗教、政治面貌、兵役、毕业院校、工作单位、社区志愿、特长、宠物 |
| 重点关爱标签 | 独居老人、特困人员、困境儿童、孤儿、留守、军人、困难、失业、失独、残疾、低保户、优抚对象 |
| 重点关注类型 | 社区矫正、安置帮教、信访、涉法涉诉、精神障碍、吸毒、邪教、疆籍、藏籍、外籍 |
| 人员角色 | 楼长、单元长、协管员 |
| 健康档案 | 基础疾病、购药频率、就医频率、重症、孕产妇 |
| 个人经历 | 学习/工作经历、上访事件 |
| 活动参与 | 社区活动情况、家庭服务需求 |

### 5.3 业务实体

| 实体 | 说明 |
|------|------|
| **VisitRecord** | 走访记录（目标对象、走访人、日期、内容、图片、标签） |
| **ConflictRecord** | 矛盾纠纷（来源、类型、涉及方、状态、处理时间线） |
| **GridWorkerScore** | 网格员绩效（五维评分：走访频次/质量、信息完善度、任务完成度/速度） |
| **Vehicle** | 车辆信息（品牌、类型、车牌、停放位置、使用状态） |
| **HousingHistory** | 居住历史（房屋ID、人员、类型、时间段、搬离原因） |
| **Notification** | 系统通知（标题、内容、类型、已读状态） |

### 5.4 核心关系

```
Grid (1) ──── (N) Person
Grid (1) ──── (N) House
Person (N) ── (N) House     [通过人房关系：现居/历史]
Person (1) ── (N) Person    [通过 FamilyRelation]
Person (1) ── (N) Tag       [标签集合]
Person (1) ── (N) VisitRecord
House  (1) ── (N) HousingHistory
```

### 5.5 审计模型

所有核心实体的 CRUD 操作统一记录：对象类型、对象ID、字段前后值、操作者、操作来源（页面/导入/移动端）、时间戳、结果状态。审计数据只读不可篡改。

## 第6章 功能需求——Web 管理端

### 6.1 综合数据管理

- **人口信息管理**：新增/查看/编辑/作废全生命周期，必填校验、身份证唯一性校验、字段级版本留痕、并发编辑冲突检测
- **批量导入**：模板驱动，预校验（必填项/身份证/日期/文本长度），失败记录导出+增量重导，批次审计
- **户籍更新**：迁入/迁出/性质变更，联动人房关系处理（即时转历史 或 生成待办提醒），变更时间线追溯
- **筛选查询**：组合条件（年龄/性别/户籍/地址/标签/常住），可保存"我的查询"，结果排序+列自定义+导出
- **标签管理**：
  - 标签总览（类型/规则/覆盖人数/状态）
  - 规则标签创建（条件组配置 → 实时预估覆盖数 → 版本号）
  - 智能标签创建（事件文本 → AI 建议 → 人工确认）
  - 标签修改（差异预览 → 重算 → 新版本）
  - 标签动态调整（重算建议队列 → 审核/拒绝 → 冻结机制）
  - 互斥标签冲突提示

### 6.2 人房一体化汇聚与分级管理

- **房屋数据整合**：楼栋→单元→房间三层结构，树形导航+右侧明细联动，唯一性+层级连贯校验，批量模板导入
- **人员-房屋绑定**：现居/历史两类，同一人同一时间仅一个现居约束，双向发起（人→房 或 房→人），并发版本号控制
- **辖区权限隔离**：角色绑定辖区节点，列表/统计/导出/下钻全受控，越权拦截+日志，临时跨辖区只读授权
- **自定义标签**：单人/批量标注，事件文本驱动建议，批次回执+一次撤销
- **标签可视化**：图表+地图联动，多标签+时间窗组合，版本口径自动对齐，小样本聚合保护
- **人员/房屋状态更新**：联动校验（空置房不允许有现居人员），状态时间线
- **更新记录追溯**：统一审计台账，按对象/时间/操作者/类型组合检索，字段级差异查看

### 6.3 多维统计查询分析

- **全域人口热力图**：多级尺度切换（街道→社区→网格），框选区域查看估计人口+占比+变化幅度
- **特定年龄段统计**：自定义年龄区间，实时计算+辖区分布+导出
- **特定标签统计**：多标签合并口径，同比/环比，标签版本提示
- **低保/失业人群统计**：专项入口，分布热力+辖区清单
- **学龄/老龄人口统计**：规则口径判定，多期趋势对比曲线
- **迁入趋势分析**：时间序列（周/月），增幅异常高亮，多辖区对比
- **迁出趋势分析**：同迁入，含季节性因素分析

### 6.4 归因分析

- **异常结果分析**：自动检测关键指标骤变，生成解释性线索，跳转时序/因子分析
- **时序分析**：按月/季度识别周期规律，多辖区并列对比，标签版本口径对齐
- **影响因子识别**：候选因子定性分级（高/中/低），线索性视图，不做因果判断
- **贡献度排名**：因子重要性排序+影响描述
- **贡献率展示**：占比结构可视化，多辖区+时间窗对比

### 6.5 数据可视化分析

- **辖区总览仪表盘**：总人口、性别比、常住/流动占比、重点人群、趋势曲线，指标卡联动下钻
- **核心指标**：老龄化率、常住人口占比、流动人口占比、年龄分布（柱状图+性别分组）、重点人员数量
- **数据下钻**：市→区→街道→社区→网格，面包屑导航，筛选条件继承
- **预警地图**：空间维度预警聚合，预警点摘要+时间切换，不暴露个体信息

### 6.6 系统配置与安全

- **用户管理**：账号全生命周期（新建/修改/禁用/启用），版本校验防并发覆盖
- **角色管理**：功能权限+辖区范围双维度配置，角色复制创建，无层级继承
- **权限管理**：功能权限精确到页面+按钮，数据权限按辖区+标签敏感级别，运行时网关校验
- **日志管理**：登录/查询/导入/导出/CRUD/权限变更全覆盖，组合检索+导出，保留周期合规

## 第7章 功能需求——九大 AI 应用场景

### 7.1 信息管理

- 人口、房屋、人房关系统一管理
- 支持批量导入，缩短存量入库周期
- 标签画像 + 统计分析，为各业务场景提供数据支撑
- **关联智能体**：数据管理智能体

### 7.2 日常走访

- AI 自动生成个性化访谈提纲
- 实时调取居民画像，提示关注要点
- 语音转文字即时记录
- AI 提炼关键诉求、生成待办事项和服务工单
- "走访前有准备、走访中有支撑、走访后有闭环"
- **关联智能体**：AI 社工助手

### 7.3 活动组织

- 社区活动全流程（创建→报名→执行→总结）
- 移动端同步支持活动查看、报名、参与
- 根据活动类型自动搜索社区人才资源库
- 自动生成可提供服务人员名单 + 被服务人员名单
- **关联智能体**：研判调度智能体

### 7.4 政策应用

- 政策文件解析，提取核心要点
- "政策找人"：自动匹配符合政策条件的目标人群
- 生成任务清单，点对点推送至网格员移动端
- **关联智能体**：研判调度智能体

### 7.5 问题处置

- 多渠道问题录入（12345热线、居民反馈、上级推送、拍照/文字/语音）
- AI 自动生成处置建议
- 类似案例参考
- 法规依据摘要
- "接诉即办、办则办好"
- **关联智能体**：AI 社工助手

### 7.6 决策辅助

- 整合人口结构、设施分布、事件频次、服务效能等多维数据

## 第8章 功能需求——移动端（山东通接入）

### 8.1 接入与认证

- 山东通"工作台"入口，免重复登录
- 复用山东通统一认证票据，自动识别身份+组织架构
- 首访同步用户资料与辖区授权边界
- 组织权限变动时自动刷新授权
- 异常拦截：票据过期、账号禁用、权限不足

### 8.2 数据采集

- **出生登记**：新生儿基础信息 + 监护人信息，唯一档案标识，冲突检测
- **入住/搬离登记**：人员检索 → 房屋选择 → 时间录入，人房关系联动创建/更新
- **居住情况**：同住人员名单、住房性质，弱关联补充信息
- **房屋状态**：有人居住/空置/出租，联动人房关系校验
- **标签信息采集**：自由文本事件描述 → AI 建议标签（"建议态"）→ 管理端确认生效

### 8.3 信息查询与核验

- **档案检索**：姓名/身份证主检索，关键信息摘要+近期变更时间线，直接发起修改
- **人员新增**：最小必填字段集，身份证唯一性校验，离线安全缓存+重试
- **人员修改**：联系方式/住址/标签建议变更，联动人房关系引导，多端并发版本冲突检测
- **人员删除**：逻辑删除，权限控制，二次确认+影响范围提示，联动关系处理引导

### 8.4 走访管理

- 走访记录表单：走访对象（人员/房屋）、走访内容（文本/语音/多媒体）、现场照片
- 时光轴：按时间线查看历史走访日志
- AI 辅助：访谈提纲生成、关键诉求提炼

### 8.5 工作台

- **待办清单**：手动创建 + 系统自动派发（规则触发/周期生成）
- **任务完结**：标记完成 + 补充内容 + 上传佐证（图片/视频）
- **绩效排名**：多维度（社区/乡镇/区）、多指标（更新条数+质量、走访条数+质量）

### 8.6 离线/弱网策略

- 本地安全缓存待提交数据
- 网络恢复后自动重试
- 数据库为唯一事实源，缓存仅保障现场提交

### 9.1 性能要求

| 指标 | 要求 |
|------|------|
| 页面首屏加载 | < 2 秒 |

- 等级保护：至少二级（建议三级）
- 传输加密：TLS 1.2+
- 存储加密：AES-256
- 敏感字段脱敏：身份证中间位掩码、手机号中间位掩码
- 法律合规：《个人信息保护法》《数据安全法》
- 权限隔离：角色+辖区双维度，越权即时阻断+日志

### 9.3 可用性

| 指标 | 要求 |
|------|------|
| 系统可用率 | ≥ 99.9% |
| 故障恢复时间（RTO） | < 4 小时 |

- 浏览器：Chrome 90+、Edge 90+
- 移动端：山东通内置浏览器
- 屏幕适配：375px - 2560px

### 9.5 审计与留痕

- 全操作审计日志
- 日志不可篡改
- 保留周期 ≥ 3 年
- 导出时敏感字段脱敏

### 9.6 数据备份

- 每日全量备份
- 实时增量备份
- 异地灾备（建议项）

系统采用 SENSORO 设计体系，已完成深色主题全面适配：

| 维度 | 规范 |
|------|------|

| 间距 | 4 / 8 / 12 / 16 / 24 px（8n 原则） |
| 主题 | 永久深色模式 |
| 背景层级 | Neutral-00（页面）→ 01（一阶卡片）→ 02（二阶卡片） |

### 10.2 布局规范

| 端 | 布局 |
|----|------|
| Web 端 | 左侧可折叠导航 + 右侧内容区，面包屑导航 |
| 移动端 | 底部 Tab 导航 + 卡片式列表 + 沉浸式表单 |

### 10.3 关键交互模式

- 人房树形导航与右侧明细联动
- 标签可视化图表 + 地图联动
- 数据下钻面包屑（多级穿透）
- 批量操作确认流程（影响范围预览 + 二次确认）
- 离线缓存同步提示

### 10.4 高风险操作保护

- 删除/批量修改/导出：二次确认弹窗
- 作废操作：不物理删除，保留审计链路
- 标签重算：差异预览 + 变更说明必填

### 10.5 数据脱敏展示

- 身份证：显示前6后4，中间掩码
- 手机号：显示前3后4，中间掩码
- 导出文件同步脱敏
