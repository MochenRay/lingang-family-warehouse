# Phase 13 简历主项目可信度加固计划

> 日期：2026-07-11
> 状态：已冻结，待执行
> 基线：`main @ bc4f1f4495793e047b7d4f625e1ef672853207ab`

## 目标

把当前“可浏览的全栈 Demo”收紧为“口径一致、主链可深问、本地可完整复验”的简历主项目，同时保留真实 Gemini 调用能力。

## 成功标准

1. 首页、人口台账、房屋台账对同一演示库显示一致总量。
2. 人房关系页不再按房屋逐条请求历史；一次打开不超过 10 个业务 API 请求。
3. 公网演示具备可配置写保护；本地开发仍可完整新增、修改、删除。
4. Gemini 请求具备输入上限、输出上限与速率限制；本地预览可完成一次真实模型响应。
5. 至少一条“人物上下文 -> Gemini -> 走访辅助输出”链路真实接通，降级状态可见。
6. 前后端关键行为有自动化测试；CI 可执行 typecheck、build、backend tests 与 frontend tests。
7. README 与演示说明准确区分真实能力、规则型能力、样例页面和后续边界。

## 垂直切片

### A. 数据口径与关系读取

- 深化分页读取 Module，统一处理 `items + total` 与多页聚合。
- 修复人口、房屋、走访等只读取前 500 条的问题。
- 人房关系历史改为聚合读取，移除 N+1。
- 以自动化测试锁定总量与请求数量。

### B. 演示安全与 Gemini 主链

- 增加 `enabled / token / readonly` 三档写入策略。
- 本地默认保留完整写能力；公网部署可切只读或令牌模式。
- 为 Gemini 增加输入、输出与速率护栏。
- 让一条走访辅助路径消费真实人物上下文；模型不可用时保留显式降级。

### C. 可复验交付

- 建立 pytest、Vitest 与 Playwright smoke 基线。
- 增加一键本地预览入口；可通过 Railway 注入既有 Gemini 凭据，但本地数据库独立。
- 重写 README 与验证说明，加入职责边界、架构、运行方式和证据链。

## 耐久架构决策

- PostgreSQL / SQLite API 是业务真相层；localStorage 只可作显式本地降级，不承诺离线写同步。
- 分页复杂度藏于 repository Interface 后，不由页面自行拼页。
- 外部 LLM 是系统 seam；真实 provider 与确定性降级均为明确 Adapter。
- 公网写保护由后端执行，前端提示不是安全控制。

## 明确不做

- 不把 Demo 冒充正式生产系统。
- 不在本轮实现完整政务账号、组织同步、辖区 RBAC 或等保体系。
- 不接真实居民、城市大脑、山东通、GIS 或 12345 数据。
- 不在未冻结迁移策略前强改现有 Person-House schema 为全量 N:N。
- 不重做全部静态展示页；保留既有入口，但补足能力边界标识。

## 并行边界与集成顺序

1. 数据分支：分页、总量、人房关系读取及对应测试。
2. 安全/AI 分支：写保护、LLM 护栏、上下文走访链及对应测试。
3. 交付分支：测试工具链、CI、本地预览、README 与验证说明。
4. 集成分支按 `数据 -> 安全/AI -> 交付` 合并；共享入口冲突由主线程处理。
